# 能量策略 energy-policy-v1

**这是可调整的工程启发式规则，不是医疗判断。**
它的目的只有一个：让调度引擎在"今天还剩多少时间与能量"这个问题上给出
**可解释、可复算、确定性**的答案。所有数值都是拍脑袋的起点，后续会随
用户反馈迭代——因此策略被版本化（`energy-policy-v1`），全部常量集中在
`packages/domain/src/capacity/energy-policy.ts`，不散落硬编码。

## 能量账本

### 基础能量点

直接使用签到能量档位 `EnergyLevel` 的数值：20 / 50 / 80。

### strain 扣减

每个负担标签扣减固定点数：

| 标签 | 扣减 |
| --- | --- |
| poor_sleep（睡眠差） | 6 |
| physical_discomfort（身体不适） | 8 |
| low_mood（情绪低落） | 5 |
| exhausting_commute（通勤耗竭） | 4 |
| meeting_heavy（会议过多） | 4 |
| urgent_deadline（截止逼近） | 3 |
| interpersonal_stress（人际压力） | 5 |
| other（其他） | 3 |

总扣减**最多 15 点**：标签是解释性的，不应把能量账本扣穿。
扣减后的调整能量不低于 0。

### 能量成本

- 固定承诺：`ceil(持续分钟数 / 30) × energyDemand`；
- 弹性任务：`ceil(任务分钟数 / 30) × energyDemand + emotionalResistance × 2`。

30 分钟是结算块：一件 45 分钟的事按两块结算，因为切换与收尾也有成本。
弹性任务的 `minimum` 形态使用最低可行版本的时间与 energyDemand，
但**保留原任务的 emotionalResistance**——降级省的是力气，不是心理阻力。

剩余能量 = max(0, 调整能量 − 承诺能量成本)。本轮只算到"剩余"为止，
不用它做任务选择。

## 时间账本

### 空闲槽位

空闲槽位 = planningWindows − commitments。一个承诺可以把窗口切成两段；
边界相接不产生零长度槽位。

### 保护性空白

按能量档位从空闲时间里预留一段"不安排任何东西"的空白：

| 能量档位 | 保护比例 |
| --- | --- |
| 20 | 30% |
| 50 | 20% |
| 80 | 10% |

状态越差，留白越多——这是产品立场，不是数学结论。
比例计算后**向上取整到 5 分钟**，且不得超过空闲时间本身。
可安排时间 = 空闲时间 − 保护性空白。

## 容量状态

| 状态 | 判定 |
| --- | --- |
| `exhausted_by_commitments` | 承诺能量成本 ≥ 调整能量，或可安排时间为 0 |
| `commitment_heavy` | 承诺占调整能量至少 50%，或固定时间占可规划时间至少 50% |
| `available` | 其他情况 |

判定按上表顺序：先判耗尽，再判偏重。所有比较使用整数算术，
相同输入永远得到完全相同的结果。

## 可解释性

分析结果除数值外还返回 `reasons`：每条含机器可读的 `code`、
人类可读的 `message` 与相关数值 `values`。UI 可以直接展示，
也可以拿 `values` 重新算一遍给用户看——这正是"可解释"的含义。
