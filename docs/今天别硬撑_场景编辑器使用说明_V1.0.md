# 场景编辑器使用说明

零基础也能完成美术拼接、坐标调整、保存到工程与布局交接

内部手册 V1.0  ·  替代 V0.9

## 0. 三分钟快速上手

第一次使用时，只要记住这 6 步：

1. 在开发环境打开 `/?view=space&sceneEditor=1`
2. 在 `Hierarchy` 里选中要调整的物件
3. 用拖拽、缩放或 `Inspector` 改坐标
4. 需要精确对齐时打开 `debugAssets=1`
5. 确认画面后点击 `保存到工程`
6. 查看 Git diff，并把本轮说明发给开发或产品

如果只是临时试摆，不想改工程文件，可以只用本地草稿或导出 JSON。

## 1. 编辑器是什么

场景编辑器是浏览器里的轻量场景排版工具，用来直接调整 `1440 x 900` 设计空间中的物件位置、尺寸、层级和显隐状态。

它解决的是“看到画面却只能口述坐标”的问题。现在可以直接在页面里选中物件，所见即所得地调整，再把结果保存回工程里的 `scene-layout.json`。

## 2. 使用条件与常用入口

### 2.1 使用条件

- 只能在开发环境使用，生产构建不会加载编辑器
- 建议使用桌面浏览器，窗口宽度不低于 `1280px`
- 开始大幅调整前，先确认 Git 工作区状态，确保知道当前基线

### 2.2 常用地址

- 编辑器：`/?view=space&sceneEditor=1`
- 校准模式：`/?view=space&debugAssets=1`

### 2.3 关键文件

- 布局数据：`apps/web/src/features/space/scene-layout.json`
- 布局协议：`apps/web/src/features/space/scene-layout.ts`
- 场景渲染：`apps/web/src/features/space/SpaceScene.tsx`
- 资产清单：`apps/web/src/features/space/asset-manifest.ts`
- 美术坐标交接：[`docs/art/scene-layout-v1.md`](file:///c:/Users/1/Documents/GitHub/today-dont-push/docs/art/scene-layout-v1.md)

## 3. 界面区域说明

- `Toolbar`：Undo / Redo / 吸附开关 / 恢复默认布局 / 清除本地草稿 / 保存到工程 / 导出布局
- `Hierarchy`：列出全部场景物件，可切换选择、显隐、锁定
- `Canvas`：直接拖动、缩放物件
- `Inspector`：输入 `x / y / width / height / zIndex`，以及 `visible / locked / keepRatio`
- `Notice`：显示保存、恢复草稿、失败等状态提示

## 4. 选择、拖动与缩放

### 4.1 选择物件

- 方法 A：在 `Hierarchy` 点击物件名称
- 方法 B：直接点击画布中的物件

选中后，Hierarchy 会高亮，Inspector 会显示属性，画布会出现控制框。

### 4.2 拖动位置

- 拖动时坐标会按设计空间换算回 `1440 x 900`
- 物件不会被允许拖出舞台边界

### 4.3 缩放大小

- 角点缩放：同时改变宽高
- 边缘缩放：改变单轴；若 `keepRatio` 开启，另一轴会按素材比例同步变化
- 最小宽高为 `20px`

### 4.4 吸附开关

吸附适合做边缘、中心线和相邻物件对齐。做最后 1-2px 微调时可暂时关闭，完成后建议重新打开。

## 5. Hierarchy 与 Inspector 的推荐用法

### 5.1 Hierarchy

- `visible` 用于临时隐藏遮挡物件
- `locked` 用于冻结已经定好的物件
- 不要把 `visible=false` 当成删除；它会进入导出和工程保存

### 5.2 推荐锁定策略

- 始终优先锁定：`sceneBackground`、`weatherOverlay`、`roomForeground`
- 定位满意后及时锁定：收音机、台灯、时钟、打印机等独立物件

### 5.3 Inspector 非法输入的处理

- 非整数：拒绝写入
- 越界：显示允许范围，画布保持原样
- 宽高过小或当前空间容纳不了：拒绝写入
- `zIndex` 不是安全整数：拒绝写入

## 6. 撤销、重做与快捷键

- `Ctrl/Cmd + Z`：撤销
- `Ctrl/Cmd + Shift + Z`：重做
- 方向键：微调 `1px`
- `Shift + 方向键`：微调 `10px`

一次连续拖拽或缩放，只会在松手时形成一个历史节点；这样 Undo 撤销的是“一次意图”，不是每个像素。

当输入框聚焦时，场景级 Undo/Redo 与方向键微调会自动屏蔽。

## 7. 本地草稿、导出与默认布局

### 7.1 本地草稿

编辑器有变更后，会在约 `300ms` 内把当前布局写到浏览器 `localStorage`：

- key：`today-dont-push:scene-layout-draft:v1`

它只属于当前浏览器，不会自动进入 Git，也不会影响其他人的电脑。

### 7.2 草稿恢复规则

- 刷新页面时，如果存在合法草稿，会优先恢复草稿
- 清除本地草稿只删除浏览器缓存，不会改当前画布
- 恢复默认布局会把当前画布重置为工程默认布局

### 7.3 导出布局

`导出布局` 会下载当前画布对应的 JSON，适合做临时对比、异步讨论或留档。

## 8. 保存到工程

V1.0 起，`保存到工程` 已正式可用。

### 8.1 它会保存到哪里

按钮会把当前布局写回：

- `apps/web/src/features/space/scene-layout.json`

保存成功后，Git 可以直接看到 diff。

### 8.2 保存期间会发生什么

点击 `保存到工程` 后，页面会显示 `正在写入工程……`，直到请求完成前：

- 禁止拖动、缩放
- 禁止 `Inspector` 修改
- 禁止 `Hierarchy` 的显隐和锁定切换
- 禁止 Undo、Redo、方向键微调
- 禁止恢复默认布局
- 禁止清除本地草稿
- `导出布局` 保持可用，便于临时导出当前画布

### 8.3 成功后的行为

客户端只有在以下 3 项都成立时，才判定保存成功：

1. HTTP 成功
2. 返回的是合法 JSON
3. `payload.status === "ok"`

保存成功后：

- 工程文件更新为当前布局
- 若当前画布仍与保存快照一致，则清除本地草稿
- 若成功响应回来时，当前画布已经比保存快照更新，则保留草稿并提示：
  `工程已保存，但当前画布还有新的未保存修改。`

### 8.4 为什么不会重复提交

编辑器内部使用同步提交锁。即使在同一时刻连续点击两次，也只会发送一个保存请求。

## 9. 自动备份与磁盘安全

### 9.1 自动备份位置

每次保存到工程前，开发保存插件都会先备份旧布局到：

- `apps/web/.scene-layout-backups/`

### 9.2 备份文件命名

备份文件名格式为：

- `scene-layout.<timestamp>.<unique>.json`

例如：

- `scene-layout.20260804T231424_972.27613602-e6ad-45be-a595-0c1327eaaa1d.json`

### 9.3 备份保留策略

- 默认只保留最近 `20` 份备份
- 备份清理只处理符合上述规则的备份文件
- 不会顺手删除备份目录里的其他 `.json`

### 9.4 写入安全

开发保存插件会按“备份 -> 写临时文件 -> 原子替换 -> 读回校验”的顺序执行。  
同一开发服务器实例中的保存请求会串行排队，不会并发写同一个 `scene-layout.json`。

## 10. 保存失败时怎么处理

### 10.1 常见失败提示

- `当前无法连接开发保存接口，请确认 Vite dev server 正在运行。`
- `开发保存接口返回了无效响应，布局未确认写入工程文件。`
- `写入工程文件失败，请稍后重试。`
- `布局校验失败，未写入工程文件。`

### 10.2 失败后的保护行为

如果保存失败：

- 当前画布会保留
- 本地草稿不会被清掉
- 自动草稿会恢复，继续保护当前画布

所以失败后不要急着重做一遍。先看提示，再决定是重试、导出 JSON，还是把当前草稿交给开发处理。

### 10.3 建议排查顺序

1. 确认是开发环境，不是生产构建
2. 确认 Vite dev server 正在运行
3. 再点一次 `保存到工程`
4. 仍失败时先 `导出布局`
5. 连同提示文案和本轮目标，一起交给开发排查

## 11. 标准美术接入流程

这一节替代 V0.9 中较松散的“正式美术替换流程”。

### 11.1 接入前，先确认资源边界

按 [`docs/art/scene-layout-v1.md`](file:///c:/Users/1/Documents/GitHub/today-dont-push/docs/art/scene-layout-v1.md) 执行：

- 舞台基准固定为 `1440 x 900`
- `sceneBackground`、`weatherOverlay`、`roomForeground` 都按全舞台接入
- 三张基础层源图统一使用 `1920 x 1200`
- `roomForeground` 的窗洞必须完全透明
- 独立物件必须是透明 PNG，阴影不得裁切
- 不得把未来动态文字烘焙进图片
- 不得把独立 props 画死进 `roomForeground`

### 11.2 标准接入步骤

1. 美术先按 `scene-layout-v1.md` 输出资源和窗洞坐标
2. 开发把资源接入 `asset-manifest.ts`
3. 若是已有槽位替换图片，继续沿用现有 `SceneItemKey`
4. 若是新增槽位，开发先补齐：
   `asset-manifest.ts`、`SpaceScene.tsx`、`scene-layout.ts`、`scene-layout.json`
5. 在编辑器中打开 `sceneEditor=1` 做摆位
6. 需要精确核对时打开 `debugAssets=1`
7. 画面确认后点击 `保存到工程`
8. 查看 Git diff，确认只包含预期的布局或资源改动

### 11.3 推荐交付方式

美术或产品交付给开发时，建议同时提供：

- 本轮目标说明
- 使用的资源版本
- 保存后的 Git diff 或导出 JSON
- 是否改动了窗洞、层级或可见性

### 11.4 新增一个独立物件时的标准顺序

1. 先确定它是否应该成为独立槽位，而不是画进 `roomForeground`
2. 在 `asset-manifest.ts` 注册素材
3. 在 `SpaceScene.tsx` 挂接渲染
4. 在 `scene-layout.ts` / `scene-layout.json` 补默认坐标协议
5. 用编辑器完成最终摆位
6. 用 `保存到工程` 固化结果

## 12. 调试与校准模式

打开 `debugAssets=1` 后，可看到：

- `1440 x 900` 舞台边界
- 每 `100px` 主网格与每 `20px` 次网格
- 水平与垂直中心线
- `windowViewport` Guide 轮廓
- 每个槽位的名称与 `x / y / width / height`

注意：`windowViewport` 现在只用于对齐窗洞协议和美术交接，不再裁切或定位背景、天气。

适用场景：

- 第一轮资源接入
- 校准窗洞
- 检查前景与独立物件的拼接关系
- 做最终像素级交付

## 13. 给产品、美术与开发的安全工作流

### 13.1 每次调整前

- 先确认当前基线 Commit
- 明确本轮只改哪些物件
- 锁定基础图层
- 确认资源命名和版本

### 13.2 每次调整后

- 普通模式检查整体构图
- 不同窗口宽度检查等比缩放
- 确认没有越界、遮挡或误隐藏
- 点击 `保存到工程`
- 查看 Git diff

### 13.3 不要这样做

- 不要在生产环境找保存按钮
- 不要把隐藏当删除
- 不要把失败后的草稿手动清空再去补救
- 不要一轮里同时改资源命名、窗洞、层级和大量坐标

## 14. 当前术语速查

- `Hierarchy`：物件列表
- `Inspector`：属性面板
- `keepRatio`：保持素材比例
- `zIndex`：层级
- 本地草稿：只存在浏览器里的临时布局
- 保存到工程：把当前布局真正写回 `scene-layout.json`
